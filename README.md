# קפה פיקולו - כרטיסייה דיגיטלית

מערכת נאמנות דיגיטלית שמחליפה את הכרטיסייה הנייר של קפה פיקולו. לקוחות
נרשמים בקישור, מקבלים כרטיס אישי שנשמר בטלפון שלהם כמו אפליקציה (PWA -
אין צורך בהורדה מחנות אפליקציות), ובעל הקפה מנהל ניקובים דרך מסך ניהול
נפרד ומוגן בסיסמה. רק בעל הקפה יכול להוסיף ניקוב - הלקוח אף פעם לא
נוגע במספר בעצמו.

## איך זה עובד בפועל

לקוח נכנס לקישור (למשל מודבק על הקופה או בעמוד האינסטגרם), ממלא שם
וטלפון, ומקבל כרטיס אישי עם עשר כוסות ריקות וקוד QR קבוע. הוא יכול
להוסיף את הכרטיס למסך הבית מהדפדפן, וזה יתנהג משם כמו אפליקציה עם
אייקון משלה.

בכל קנייה, הלקוח פותח את הכרטיס ומראה את קוד ה-QR. בעל הקפה סורק אותו
במסך הניהול שלו (טלפון או טאבלט נפרד, מחובר עם שם משתמש וסיסמה) ולוחץ
"הוספת חותמת". הכרטיס של הלקוח מתעדכן אצלו לבד תוך כמה שניות, בלי
שהוא צריך לרענן. אחרי עשר ניקובים מגיעה כוס חינם - בעל הקפה לוחץ
"מימוש פרס" והמונה חוזר לאפס.

אם אין גישה למצלמה, יש גם חיפוש ידני לפי מספר טלפון במסך הניהול.

## למה זה בטוח מרמאות

| הגנה | איך זה עובד |
|---|---|
| מספר הניקובים חי רק בשרת | הלקוח לא שולח ולא קובע שום מספר - הוא רק מציג מזהה. השרת הוא מקור האמת היחיד. |
| רק בעל הקפה יכול להוסיף | כל הוספה/מימוש דורשת התחברות עם סיסמה. מזהה חבר הצוות שמבצע את הפעולה נלקח אך ורק מה-session המאומת שלו, לא מהבקשה שנשלחת. |
| יומן ביקורת מלא | כל ניקוב וכל מימוש נשמרים לצמיתות עם מי ביצע ומתי - אפשר לבדוק היסטוריה מלאה בכל רגע. |
| הגנה מפני סריקה כפולה בטעות | אם אותו לקוח נסרק פעמיים ברצף תוך פחות מעשר שניות, הניקוב השני נדחה. |
| סיסמאות מוצפנות | סיסמת הצוות לא נשמרת בטקסט גלוי בשום מקום. |
| הגנה על ההתחברות | מספר ניסיונות סיסמה שגויה מוגבל בזמן, נגד ניחוש. |

## הרצה מקומית

דרוש Node.js גרסה עשרים ואחת ומעלה.

```bash
npm install
cp .env.example .env
```

לפני ההרצה, לפתוח את `.env` ולוודא:
- `SESSION_SECRET` - ליצור ערך אקראי אמיתי עם `openssl rand -base64 32`
- `OWNER_USERNAME` / `OWNER_PASSWORD` - פרטי ההתחברות הראשוניים של בעל
  העסק (ייווצרו אוטומטית בפעם הראשונה)

```bash
npx prisma migrate dev --name init
npm run dev
```

זה גם מריץ אוטומטית את יצירת משתמש ה-owner. אפשר גם להריץ בנפרד:
`npm run db:seed` (לא יוצר כפילות אם המשתמש כבר קיים).

האתר עולה בכתובת `http://localhost:3000`. עמוד הבית מפנה להצטרפות
(`/join`), וכניסת הצוות היא ב-`/staff/login`.

לבדיקה נוחה של מסד הנתונים: `npm run db:studio`.

## פריסה לאינטרנט

הפרויקט הוא אפליקציית Next.js רגילה, ניתן לפרוס על כל שירות שתומך
ב-Node.js (Railway, Render, Fly.io, VPS עצמאי וכו').

**חשוב**: מסד הנתונים כרגע הוא קובץ SQLite מקומי (`prisma/dev.db`) -
מצוין לפיתוח ולשרת יחיד עם דיסק קבוע, אבל **לא מתאים** לפלטפורמות
serverless כמו Vercel (שם מערכת הקבצים זמנית ולא משותפת בין הפעלות).
לפריסה כזו יש להחליף ל-Postgres מנוהל (Vercel Postgres, Neon, Supabase)
או ל-Turso, לעדכן את `DATABASE_URL` ואת `provider` ב-`prisma/schema.prisma`
בהתאם, ולהריץ מחדש `prisma migrate deploy`.

לפני פריסה בפועל:
1. להגדיר את כל משתני הסביבה מ-`.env.example` אצל ספק האחסון.
2. **סריקת המצלמה בדשבורד הצוות דורשת חיבור מאובטח (HTTPS)** - כמעט
   כל שירותי האחסון נותנים את זה אוטומטית, אך אם מריצים על דומיין
   פרטי בלי HTTPS הסריקה פשוט לא תעבוד (זו מגבלת דפדפן, לא באג).
3. **מיד אחרי הפריסה הראשונה, להתחבר ולהחליף את סיסמת ה-owner** -
   כרגע אין מסך "שינוי סיסמה" בממשק, אז זה נעשה כרגע ישירות דרך
   `npm run db:studio` (לשנות את `passwordHash` בעזרת ריצת bcrypt, או
   ליצור seed script חדש) - הרחבה טבעית לעתיד.

## הוספת עוד חברי צוות

כרגע יש רק את משתמש ה-owner שנוצר אוטומטית. הוספת עובד נוספת נעשית
דרך `npm run db:studio` (יצירת שורה חדשה בטבלת `StaffUser` עם סיסמה
מוצפנת), או בכתיבת סקריפט קטן בהשראת `prisma/seed.ts`. תמיכה ב-API
ייעודי להוספת עובדים (מוגבל לבעלים בלבד) היא הרחבה טבעית להמשך.

## מגבלות ידועות

- מספר הניקובים הנדרש למשקה חינם קבוע בקוד (`STAMPS_REQUIRED` ב-
  `src/lib/config.ts`, ברירת מחדל עשר, כמו הכרטיס הפיזי המקורי).
- שינוי "start_url" של ה-PWA הוא גלובלי לכל האתר ומצביע על הכרטיס
  האחרון שנצפה במכשיר - לכן לא מומלץ שחבר צוות "יתקין" את האפליקציה
  מהמכשיר שלו; לדשבורד הניהול עדיף סימנייה רגילה בדפדפן.
- הגנת ניסיונות ההתחברות פועלת בזיכרון השרת - אם פורסים על כמה
  שרתים מקבילים בו-זמנית, ההגנה היא ברמת שרת בודד ולא משותפת ביניהם.
  מספיק לעסק יחיד קטן; שדרוג עתידי טבעי הוא מעבר ל-Redis.
